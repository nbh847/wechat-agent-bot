# 决策 001：项目内维护最小 iLink 通道适配器

状态：已确认

确认日期：2026-08-13

## 决策

WeChat Agent Bot 使用微信 iLink Bot API 作为微信通道，在项目内维护最小 TypeScript 适配器，不在第一版运行链路中使用 `@wechatbot/wechatbot` 或其他第三方微信 SDK。

腾讯官方 `Tencent/openclaw-weixin` 的公开源码是协议字段、请求行为和兼容性判断的基准。第三方 SDK 只作为参考材料，不作为事实来源。

## 当前所需能力

- 扫码登录和二维码过期刷新。
- 登录凭证、消息游标和会话上下文的本地安全持久化。
- 文本消息接收和文本回复。
- token 失效识别和重新登录提示。
- 消息去重、有限重试、可停止的长轮询和脱敏日志。

第一版不实现图片、视频、语音、文件、多账号、群聊、公众号、企业微信或通用机器人框架。

## 原因

- 本机已通过腾讯官方协议行为完成两轮真实微信文本收发和免扫码重启恢复。
- `@wechatbot/wechatbot@2.2.0` 的二维码状态查询存在已证实的超时处理缺陷。
- 当前产品只需要个人使用的文本指令入口，第三方 SDK 的媒体、多租户和中间件能力不解决当前问题。
- 项目内薄适配器更容易逐字段对照官方实现，并在产生错误语义的协议责任层修复问题。

## 代价

- 项目需要跟踪腾讯官方仓库的协议变化。
- 登录、轮询、重试、持久化和去重需要自己测试和维护。
- 将来增加媒体能力前需要重新评估是扩展适配器还是引入已验证的 SDK。

## 重新评估条件

只有出现以下任一情况时，才重新评估第三方 SDK：

- 当前需求明确需要媒体或多账号能力，项目内实现成本明显上升。
- 候选 SDK 已修复实测缺陷，并通过本项目相同的端到端回归验证。
- 腾讯发布面向独立 Agent 的正式 SDK 或更稳定的官方接入方式。

## 上层安全边界

iLink 只负责消息通道，不授予跨项目写权限。微信任务可以读取工作区内其他项目；对 `wechat-agent-bot` 之外任何项目的写入或状态变更，上层任务系统必须先取得散帅针对任务 ID、目标项目和具体动作的二次确认。通道层不得把扫码登录成功解释为跨项目写入授权。
